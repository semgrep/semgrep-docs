## 🤖 Semgrep Multimodal

### Added

- **[Semgrep Agentic Workflows](/workflows/overview)** is now in public beta. Agentic Workflows run multi-step AI-enabled detection pipelines from Semgrep AppSec Platform, combining program analysis, deterministic tools, and constrained AI-based reasoning to produce reviewable security issues. To get started, see [Get started with Semgrep Agentic Workflows](/workflows/get-started).

### Fixed

- Fixed an issue where customers were required to enable Semgrep Managed Scans before they could run an on-demand AI-powered detection scan.

## 🌐 Semgrep AppSec Platform

### Added

- Webhook validation and test failures now show specific reasons, including HTTPS required, could not parse, DNS lookup failed, private address, HTTP status, and timed out.

### Fixed

- Fixed an issue where an auto-ignore automation could revert a manually triaged finding back to **Provisionally ignored** on other matching issues.
- Fixed an issue where a failed namespace lookup for a personal access token could incorrectly resolve to the token owner's account instead of surfacing an error.
- Fixed an issue where **Provisionally ignored** findings could not be reopened from the finding **Details** page.
- Fixed an issue where Semgrep deleted a Slack notification channel mapping when the bot lacked permission to post to a private channel, instead of only when the channel was actually deleted.

## ⛓️ Semgrep Supply Chain

### Changed

- Rolled out a default Supply Chain incident notification policy to all Supply Chain customers using [unified policies](/semgrep-appsec-platform/unified-policies/overview). Organizations can configure a Slack channel to be notified during an ongoing supply chain incident, including whether they may be affected based on their most recent SBOM. The incident policy page has been redesigned to stand apart from regular policies, and Semgrep now warns when a configured Slack channel cannot receive bot messages.
